# v1.1.0 — five additive seams, and the debt the review board found

**2026-08-21** · [changelog](../changelog/v1/v1.1.0.md) · Packagist: `egl/utils`

The first release after the freeze. **Nothing in the 1.0 API changed** — every addition below is
additive under [ADR-0059](../adr/0059-freeze-the-api-at-1-0-0-with-internal-symbols-outside-the-frozen-surface.md),
so `composer require egl/utils:^1.0` keeps resolving and upgrading needs no code changes on your
side.

```bash
composer require egl/utils:^1.1
```

## What is new

Milestone 14's five seams. Each exists because the alternative was every consumer writing it again:

| | |
|---|---|
| **`Support\SystemClock` / `FrozenClock`** | PSR-20 `ClockInterface`. Time becomes an injected dependency, so a test can freeze it instead of sleeping. |
| **`Str::ulid()` / `Str::uuidV7()`** | Time-sortable identifiers. A random v4 UUID fragments a B-tree index at enterprise table sizes; these carry a 48-bit millisecond prefix, so inserts stay at the right-hand edge. |
| **`Persistence\PageRequest` / `Page`** | Pagination values that **refuse an unordered query** — `LIMIT`/`OFFSET` without `ORDER BY` returns rows in an order the engine never promised, which is how page 2 silently repeats a row from page 1. |
| **`Security\Hmac`** | A detached signature for signed URLs and webhook verification. The algorithm never travels inside the token, so a caller cannot be talked into verifying under a weaker one. |
| **`Security\RateLimiter`** | A token bucket per key behind a compare-and-swap store, with `ArrayRateLimitStore` (one process) and `FileRateLimitStore` (one machine). |

**Read `RateLimiter`'s docblock before wiring it.** A rate limit exists at the scope its store is
shared and nowhere else: behind a load balancer, a per-machine store means each node enforces its
own limit, so the effective limit is N× the configured one. This library ships the algorithm and the
seam, deliberately not a network client.

## What is smaller

**Your `vendor/` directory.** The Packagist archive was shipping the whole monorepo — tests,
benchmarks, all 70 ADRs, the tooling, CI config, and the unpublished bridge package: 524 files. It
now carries production code, `LICENSE`, `README.md` and `composer.json`. **120 files.**

Nothing was removed from the repository; only from the archive
([`.gitattributes`](../../.gitattributes)).

## What is now checked that was not

Four claims this project made about itself were not enforced by anything. They are now, and each
gate shipped with a proof that it can fail:

- **Per-diff coverage.** The 90% floor is measured on the whole tree, so an untested addition rode
  inside the headroom without the total moving. The diff is now measured too.
- **Documentation links.** Every relative link in tracked Markdown resolves, and a `§ "Section"`
  reference names a real section. Its first run found **nineteen** broken links.
- **The API-docs build.** `AGENTS.md` had listed "phpDocumentor builds without warnings" as a
  mandatory gate since the repository was generated, with no config and no job anywhere. There is
  now a build, a gate, and a published reference.
- **The Release body you are reading** is rendered from
  [`docs/releases/v1.1.0.md`](v1.1.0.md) rather than written by hand, with relative links rebased to
  this tag. Hand-editing it is no longer an input to the record.

## Things worth knowing before upgrading

- **`Errors\Result` and `Dto\Collection` generic annotations were rewritten** from `@return self<U>`
  to `@return Result<U>` / `@return Collection<TItem>`. **No signature changed** and PHPStan reads
  both identically — but if you extend either class and copied its annotations, phpDocumentor
  rejects the `self<T>` form and drops the tag from generated docs.
- **`Persistence\Page` computes `pageCount()` as `1` for an empty result set**, not `0`. A search
  with no results is on page 1 of 1.
- **`RateLimitDecision::retryAfterSeconds()` rounds up**, so a client is never told to come back
  before its token exists.
- Requires **PHP 8.1+** with `ext-pdo` and `ext-fileinfo`; `psr/clock` joins `psr/container` and
  `psr/log` as an interface-only dependency. `ext-iconv` and `symfony/html-sanitizer` remain
  *suggested*, and each refuses at the call site rather than degrading when absent.

## Known limits, stated rather than discovered

- **The `egl/utils-psr7-bridge` package is still not published.** Its source lives in this
  repository under `packages/`, its contract suite runs on every PR against two PSR-17
  implementations, and its publication needs the split repository configured
  ([issue #120](https://github.com/danielPoloWork/egl-util-php/issues/120)).
- **`Escaper::attr()` assumes an unquoted attribute** — an escaper cannot see its call site, and the
  two possible assumptions are asymmetric.
- **`Collection<T>`'s genericity is static-analysis only.** `@template` plus PHPStan at max level,
  with no runtime enforcement.
- **`EmailAddress` is stricter than RFC 5321** in one visible way: `filter_var()` refuses a bare
  hostname (`user@example`), which real intranet addresses use.
- **`NativeMailer`'s envelope sender is a `sendmail` option**, so it is a no-op on PHP's Windows SMTP
  transport.

## How this release was published

**The `v1.1.0` tag is unsigned**, so `release.yml`'s `The tag must be signed` step failed and both
the tagged-tree 8.1/8.2/8.3 matrix and the draft-Release job were skipped. This Release was
published by hand.

This is the third release in a row to fail that step, and it is a known, deliberate position rather
than an oversight: no signing key is registered on the account, and creating one is a maintainer
action tracked as [issue #115](https://github.com/danielPoloWork/egl-util-php/issues/115). It is
recorded here for the same reason it was recorded for `v1.0.0` — a release document that contradicts
its own audit trail on a supply-chain fact is the worst possible place to be wrong.

**What that does and does not undermine.** Every number below was measured on the pull request for
this release's commit, where the full matrix ran. What is missing is the independent re-run *at the
tag*: nothing mechanically re-verified that the published tag and the verified tree are the same
thing. If you need that assurance, verify the tag against the commit it names before depending on
this release.

## Verification behind this release

Measured on the release pull request, not re-run at the tag, for the reason above. The suite on PHP
8.1, 8.2 and 8.3; ≥ 90% total line coverage enforced **and** the per-diff floor; PHPStan at max
level; PHP-CS-Fixer (PSR-12); deptrac layer rules with zero uncovered; Infection's mutation score
against its 70% floor; `composer audit` and a `--prefer-lowest` install; the absolute NFR budgets and
the same-runner relative regression gate; documentation links resolved; and the API-docs build gated
on phpDocumentor's own report rather than its exit code. Every performance claim in the documentation
is backed by a benchmark under `src/bench/` — the methodology and the honest caveats are in
[`docs/benchmarks/`](../benchmarks/).
