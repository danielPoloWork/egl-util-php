# Software Specification: EGL PHP Utility Library (PHP 8.1+)

> Rendered from the intake interview (Phase 5). Frozen contract: diverging implementation
> updates this spec in the same PR or adds an ADR superseding the relevant section.

**Revision r32** — 2026-08-28. See [Revision history](#revision-history).

## 1. Objective & Business Context

Provide EGL PHP projects (framework-based and native/legacy) with a modern utilities library — Composer package egl/utils, PSR-4 namespace D4np\Utils\, PHP 8.1+ — offering typed readonly DTOs, explicit-mechanism security helpers, safe PDO access, hardened session/CSRF handling, and a minimal PSR-11 DI container, replacing ad-hoc per-project solutions (associative-array DTOs, blocklist sanitizers, string-built SQL, silent PDO error modes).

## 2. Functional Requirements

- FR-01 DataTransferObject: hydrate typed readonly DTOs from arrays via reflection with per-class metadata caching; strict mode default (unknown key -> UnknownKeyException), lenient() opt-in; missing non-nullable key -> MissingKeyException (RFC-0001 R-4 addition); nested DTOs and Collection<T> hydrate recursively; type mismatch -> TypeMismatchException naming the path
- FR-02 WithersTrait: with(...) wither semantics producing modified clones of readonly DTOs, absorbing the PHP 8.1->8.3 readonly-clone difference per version
- FR-03 Collection<T>: functional array wrapper (map/filter/reduce); genericity static-analysis-level only (@template + PHPStan max); optional runtime instanceof guard flag
- FR-04 Container: minimal PSR-11 container — constructor autowiring (cached reflection), singletons/factories, no compilation; non-goals per imported ADR-001 (no attributes, no lazy proxies, circular deps throw with path)
- FR-05 ServiceProvider: abstract base for registering container definitions
- FR-06 DatabaseConnection: PDO wrapper with pinned safe defaults — ERRMODE_EXCEPTION, utf8mb4 on MySQL, real prepares (EMULATE_PREPARES=false), FETCH_ASSOC
- FR-07 QueryBuilder: fluent SQL builder — values always bound as parameters; identifiers allowlisted (^[A-Za-z_][A-Za-z0-9_]*$) and driver-quoted; ORDER BY direction is an enum; LIMIT/OFFSET cast to non-negative int
- FR-08 Transaction: closure-scoped transactions — automatic rollback on any exception and rethrow; nested calls use savepoints
- FR-09 Escaper: context-aware output escaping — html() (ENT_QUOTES|ENT_SUBSTITUTE, UTF-8), attr(), js() (hex), url() (rawurlencode)
- FR-09b Sanitizer::richText(): user-authored HTML delegated to symfony/html-sanitizer (optional dependency) with a curated allowlist profile; no hand-rolled tag stripper
- FR-10 Sanitizer::sqlLikePattern(): escape %/_/escape-char in user input used inside LIKE patterns (wildcard-injection defense; values still bind as parameters)
- FR-11 Hash: password_hash wrapper, Argon2id default; availability via defined('PASSWORD_ARGON2ID'); bcryptFallback: true default logged at WARNING or false to fail fast; self-describing hashes; needsRehash() upgrades on login; the fail-closed posture is additionally reachable as the named constructor `Hash::strict()` (issue #102, ADR-0079) — the `true` default cannot be inverted before a MAJOR under ADR-0059, so a logger-less construction still degrades quietly and a deployment that cares calls `strict()` or asserts `algorithm()`
- FR-12 CsrfToken: CSPRNG token generation + constant-time validation (hash_equals), per-session storage, optional per-form scoping (lives in the Http group per RFC-0001 R-1 placement note)
- FR-13 Request: typed superglobal reader ($_GET/$_POST/$_SERVER/$_FILES); optional PSR-7 bridge per imported ADR-002
- FR-14 Response: headers/JSON/status helpers; same bridge
- FR-15 Session: secure session API — cookie_httponly, cookie_secure, cookie_samesite=Lax at start; regenerate() wraps session_regenerate_id(true) for login transitions
- FR-16 Result: success/failure wrapper for application services (map/flatMap/orElseThrow)
- FR-17 Logger: PSR-3 file/console logger
- FR-18 ExceptionHandler: fatal-error capture, JSON problem responses for API calls; never leaks traces in production mode (env-gated)
- FR-19..21 Str: slug() (transliteration via ext-intl when present), uuid() (v4 from random_bytes), random() (CSPRNG alphanumeric tokens)
- FR-22..23 File: write()/read() flock-guarded, atomic write via temp+rename; writeStream() streams to the temp file under the same discipline, for producers whose output must not be buffered (r5, spec NFR-12); update() performs a read-modify-write under ONE exclusive lock, which read()+write() cannot express (r6, ADR-0038); mime() via Fileinfo (never trusts extensions)
- FR-24 Env::get(): env reads with correct boolean coercion ('false' -> false)
- FR-25 Json: encode()/decode() with JSON_THROW_ON_ERROR; library JsonException wraps and rethrows PHP's native \JsonException (RFC-0001 R-7)
- FR-26 Exception hierarchy: UtilsException <- DatabaseException, HydrationException (<- UnknownKeyException, TypeMismatchException, MissingKeyException), HttpException, FileException, JsonException

**r3 addendum (RFC-0002)** — normative detail in
[RFC-0002](../rfc/0002-application-layer-groups-from-legacy-intake.md); one error-model rule
spans all of it: **no silent sentinel returns** — every new failure path throws a typed
exception in the FR-26 hierarchy (new: InvalidUrlException, CsvException [added r5],
SequenceExhaustedException,
HttpClientException, RouteNotFoundException, MethodNotAllowedException, CryptoException,
MailException).

- FR-27 Url: parse/normalize/build value object; absolute URLs only; refuses C0/DEL control characters up front (parse_url() rewrites them to "_" rather than rejecting them — ADR-0036); refuses a scheme downgrade (https->http, wss->ws, ftps/sftp->ftp; an unknown target scheme is allowed through — recorded limit); query preserved byte-exact until edited, composed per RFC 3986, null values refused at any depth
- FR-28 Csv + Delimiter enum: streaming write/read (memory O(row)), typed failures (never boolean), atomic write via File::writeStream(); PHP's non-RFC-4180 backslash escape DISABLED on every call — the default corrupts any field ending in a backslash (ADR-0037); a single empty field is written as "" (fputcsv emits a bare newline, which is lost on read) and a zero-column row is refused; blank lines skipped on read, a quoted empty field is not; formula-guard opt-in (default off — input-mutilation lesson, spec §1), leaders = OWASP's `=` `+` `-` `@` plus tab and CR
- FR-29 CsvSerializable: csvHeader()/csvRow() contract, with the pairing ENFORCED — Csv::write() takes the header from the first item and refuses any row whose width disagrees (ADR-0037)
- FR-30 Lookup: immutable code→label map; label() throws on a missing key, labelOr()/tryLabel() tolerant
- FR-31 Str additions: collapseWhitespace(), nullIfBlank(), transcode() (strict default, lossy opt-in), multibyte-safe padLeft()/padRight(), shortClassName(), pascalCase()
- FR-32 FileSequence: rolling counter with an explicit cap (SequenceExhaustedException); never wraps silently. The whole read-modify-write runs under ONE exclusive lock via File::update() — read()+write() as two separately locked calls loses an increment, which for a sequence is a duplicate identifier (ADR-0038). A corrupt state file is refused, not reset (resetting re-issues the whole window) and is left on disk as evidence; an absent or blank file is a legitimate fresh start. The window is a caller-supplied opaque string (no timezone decision inside the library); recorded limit: windows cannot be ordered, so ANY window change resets — callers must supply a monotonically advancing window. peek()/remaining() are advisory and unlocked.
- FR-33 SqlStatement (Database): immutable SQL+params value — the only shape connection-side execution accepts; hand-written dialect SQL always travels with its binds. Enforced by TYPE, not by convention (r8, ADR-0041): private constructor, three named entry points — literal() taking a `literal-string` (PHPStan max refuses interpolated or concatenated text, and still permits hand-written dialect SQL with placeholders), fromQueryBuilder() taking the builder object so no SQL text crosses as a bare argument, and composed() as the single named escape hatch for runtime-assembled text, with zero in-library uses so `grep composed(` is the review list
- FR-34 Repository (Persistence): abstract base — fetchAll/fetchOne/execute/withTransaction; rows normalized (FR-36) then hydrated via the shared Hydrator; every failure throws DatabaseException. Realized (r10, ADR-0043) with NO try/catch anywhere in the class: the requirement is satisfied by omission, since DatabaseConnection, the hydrator and RowNormalizer each raise a typed failure that must propagate untouched — asserted directly against the class's own source, because an absence is what a suite loses unnoticed. Hydration stays STRICT (ADR-0008), so a projected column the DTO does not declare raises and SELECT * into a typed DTO fails by design; hydrate() is a protected, non-final seam for a subclass wanting lenient. Normalization is OPT-IN (?RowNormalizer = null — the question ADR-0042 deferred): without one, rows hydrate exactly as the driver returned them. execute() returns the affected-row COUNT, never a boolean: 0 is a fact only the caller can interpret. withTransaction() delegates to Transaction (ADR-0016) and passes the repository to the closure
- FR-35 TableGateway (Persistence): Table Data Gateway over one table — find/all/findBy/findOneBy/insert/update/updateBy/delete/deleteBy, with identifiers allowlisted and values bound by construction. **Corrected (r11, ADR-0044): "over QueryBuilder" was not implementable — QueryBuilder is SELECT-only and always was.** Reads compose through QueryBuilder; writes through the new FR-33b MutationBuilder; both share one Identifier, so there is one allowlist rather than two copies. Extends Repository (FR-34), inheriting hydration, opt-in normalization, transactions and the no-catch property. Three behaviours are normative: empty criteria are REFUSED on every filtered operation (an empty array is what an unvalidated request filter collapses to; all() is the named whole-table read), reads PROJECT THE DTO rather than SELECT * (strict hydration, ADR-0008), and the table name is allowlisted at CONSTRUCTION as well as per statement (fail fast at wiring time, ADR-0022). Non-goals: no JOIN, aggregates, upsert, identity map, change tracking or lazy loading — RFC-0002 Alternative #1
- FR-33b Identifier + MutationBuilder (Database, r11, ADR-0044): the FR-07 allowlist and per-driver quoting extracted into one class both builders share — a copied allowlist is one edit from two rules, and the weaker decides — plus INSERT/UPDATE/DELETE composition as named constructors, values bound, `null` criteria rendering IS NULL, and UNQUALIFIED WRITES REFUSED (an UPDATE or DELETE with empty criteria applies to every row). Enters SqlStatement through a fourth named door, fromMutation(), taking the builder object; composed() keeps its zero in-library uses and therefore keeps its meaning as the review list (ADR-0041)
- FR-36 RowNormalizer (Persistence): strict/lossy charset transcode + trim + empty→null as one explicit, testable policy object. Defaults are asymmetric by decision (r9, ADR-0042): trim ON (fixed-width CHAR padding is a storage artifact), transcode/collapseWhitespace/blankToNull OFF (each changes data, and spec §1 forbids a library rewriting a consumer's values unasked). Step order is FIXED, not configurable: transcode first (trimming bytes not yet in the target encoding is only safe for an ASCII-compatible source), then trim/collapse, then blank→null last so it judges the value the earlier steps produced. Strict by default: an unconvertible value raises DatabaseException naming the COLUMN; $lossy = true opts into dropping. Keys and non-string values (int/float/bool/null, BLOB resources) are never touched
- FR-37 HttpClient: stream-context transport (no ext-curl), JSON/raw bodies, TLS options stated explicitly in every context (never inherited from the process default), a per-phase timeout AND a wall-clock ceiling on the whole exchange, redirects off by default, http/https only, outbound header injection refused, HttpClientException for a request that produces no response (any status the origin produced is returned as an HttpResponse; when redirects are followed, the response reported is the LAST hop's — status, headers and body from one exchange, r15/ADR-0052); deliberately not PSR-18 (native wrappers + optional bridge, RFC-0001 Alt. #3). **Revised at r14 (item 11.1, ADR-0049)** — r3 said "explicit connect/read timeouts"; PHP's http wrapper exposes one `timeout` knob that covers connect *and* each read, re-arming per phase, so separate values are not available and a per-phase value alone does not bound a request. The two limits above are what the wrapper can actually deliver
- FR-38 Router: method+path matching with {param} extraction; 404 vs 405 with Allow; callable handlers; non-goals: middleware, route caching, attribute discovery
- FR-39 ApiEnvelope: readonly envelope (status, code, messages, data) with outcome constructors (ok/created/updated/deleted/empty/invalid/notFound/failed/caught); message strings caller-supplied — localization stays app-side
- FR-40 Crypto + SecretKey: AES-256-GCM, versioned v1. base64url compact token; decrypt() throws CryptoException on any failure; ext-openssl suggested with constructor refusal when absent; #[SensitiveParameter] on secret-bearing signatures (inert on the 8.1 floor, effective 8.2+)
- FR-40b SecretKeyRing (Security): key rotation for FR-40's tokens (issue #114, ADR-0083). `SecretKeyRing::of(current, ...previous)` holds the key new tokens are encrypted under plus those still accepted for decryption. Key ids are **derived, not assigned** — `hash_hkdf('sha256', bytes, 4, 'egl/utils:keyid:v1')`, so an id is a PRF output that cannot be inverted to key material and is stable for the same key in any process with no registry to maintain. A ring **refuses two keys whose ids collide** (in practice, the same key listed twice), because a ring that cannot tell its keys apart would decrypt with the wrong one and report the failure as a tampered token. `Crypto` constructed with a ring emits `v2.` = base64url(keyId (4 bytes) || nonce || ciphertext || tag), and **the key id is GCM's AAD** so the authentication tag covers it: a substituted id cannot verify, and neither can a `v2.` body replayed as a `v1.` token. An **unknown key id fails closed** — never retried against the ring's other keys, which would make retiring a key inoperative. `Crypto` constructed with a bare `SecretKey` produces **byte-identical `v1.` tokens**, which is what keeps this additive under ADR-0059; a ring also reads `v1.` tokens by trying each key, so adopting one is a migration rather than a cutover. The derivation label and the `keyId || ...` layout are the shared convention FR-48's `Hmac` adopts when its own rotation item lands, with the id covered by the MAC rather than by an AAD
- FR-41 Level + LevelFilteredLogger: backed enum mapping to PSR-3 level strings with ordering; min-level PSR-3 decorator
- FR-42 MultiLogger + LoggerFactory: PSR-3 fan-out over N loggers; one config array → channel map; no Monolog dependency (NFR-08)
- FR-43 EmailAddress + MailMessage: validated address value object; readonly message; CR/LF/NUL in any header-bound value refused at construction (SMTP header-injection defense)
- FR-44 Mailer + NativeMailer: transport interface + mail() implementation configured explicitly via constructor (no global ini_set); failures throw MailException; non-goal: an SMTP client implementation
- FR-45 SystemClock + FrozenClock (Support): the sanctioned time seam — both implement `Psr\Clock\ClockInterface`, and every time-touching API added from r17 on accepts the interface rather than reading system time itself (`psr/clock` is the third interface-only require, NFR-08's posture). `SystemClock::now()` returns a **fresh** `DateTimeImmutable` per call, in PHP's default timezone unless a `DateTimeZone` was injected at construction — instants are timezone-independent for arithmetic, which is every in-library use. `FrozenClock` is the shipped test double and **deliberately mutable**: `advance(DateInterval)` moves the held instant, cumulatively, honouring inverted intervals (time moving backward is a first-class clock-skew scenario, ADR-0061 §5). Construction cannot fail on either: both take objects, not strings, so validation is the type system's. Realized r17 (item 14.1, ADR-0062); verification is standard unit coverage — no named suite, since no distinct technique is involved

- FR-46 Str sortable identifiers (Support): `Str::ulid()` (26 Crockford-Base32 characters) and `Str::uuidV7()` (RFC 9562's time-ordered layout, in the familiar 36-character form) — a 48-bit millisecond timestamp in the leading bits, then CSPRNG entropy under `Str::random()`'s discipline, so **sorting the strings sorts them by generation time**: the property a v4 UUID lacks, and why a random UUID primary key fragments a B-tree index at enterprise table sizes. Both ship because neither substitutes for the other: v7 is valid anywhere FR-19..21's `uuid()` is (a UUID column, cast or validator), ULID is shorter, separator-free and drawn from a transcription-safe alphabet. Both take an optional `Psr\Clock\ClockInterface` (FR-45) so conformance vectors pin against a fixed instant. **Ordering within a single millisecond is explicitly NOT guaranteed** — identifiers from the same millisecond share a timestamp prefix and are ordered only by their random tails; guaranteeing otherwise needs cross-call state in a static method, and the index locality that motivates the format is a millisecond-granularity property the guarantee does not improve. That decision is pinned as a **mechanism** (the class declares no properties), because no behavioural assertion can see it: a monotonic implementation passes every other test. **An instant outside 48 bits is refused, never truncated** — a wrapped timestamp is a well-formed identifier that sorts wrongly, silent corruption of the one property the format exists for. Realized r18 (item 14.2, ADR-0063); budget NFR-15
- FR-47 PageRequest + Page<T> (Persistence): one window over a result set, and that window's result. `PageRequest::of(page, size, withTotal = true)` is **1-based** (the form a human reads) and derives the 0-based offset once; a page below 1, a size below 1, or an offset that would overflow PHP's integer range is **refused, never clamped** — clamping is how an unvalidated `?page=0` becomes page 1 and nobody learns the request was malformed (FR-35's empty-criteria reasoning, applied to a different unvalidated parameter). `Page<T>` carries the hydrated items, the echoed window, and — when asked for — the total; genericity is `@template` + PHPStan max, **static-analysis only**, the same honest limit FR-03's `Collection<T>` carries. **A total that was never counted throws** rather than answering 0 or null (a zero meaning "not counted" renders as "no results" over a table that is not empty), with `hasTotal()`/`totalOr()` as the tolerant forms — FR-30 `Lookup`'s three-way missing-value policy reused. `pageCount()` is 1 for an empty result set, never 0; `hasNextPage()` is derived from the total rather than guessed from a full window, which is wrong exactly on the last page of an evenly divisible table. Reads: `Repository::fetchPage(QueryBuilder, PageRequest, dtoClass)` and `TableGateway::paginate()`/`paginateBy()`. **An unordered query is refused** — SQL promises no row order without ORDER BY, so consecutive windows may repeat one row and skip another while every page looks valid; the gateway orders by its own key column (unique by FR-35's definition, so the split is total) rather than pushing the decision onto callers, which is the opposite answer to `all()`'s deliberate absence of ordering and follows from the same rule: never invent an ordering the caller does not need. **The total costs a second statement** via `QueryBuilder::asRowCount()`, a builder clause rather than composed text — `COUNT(*)` cannot pass the FR-07 allowlist, and producing it inside Persistence would spend `composed()`'s zero-in-library-uses property (ADR-0041). Window-function totals rejected on portability: every database proof here is SQLite-only. Realized r19 (item 14.3, ADR-0064); verification extends suite T-13 to the new read paths rather than claiming a new suite

- FR-48 Hmac (Security): keyed authentication for signed URLs and webhook signatures. `sign(message, ttl = null)` returns a **detached** signature token — `v1.` + base64url(expiry (8 bytes, big-endian) || raw MAC) — with the message left where it lives (a URL's query, a webhook body), because `verify(message, token)` is handed it back anyway. The `v1.` grammar is ADR-0054's, reused so the Security group has one token shape. **The MAC covers the expiry as well as the message**, at a fixed 8-byte width so the concatenation needs no delimiter — an unauthenticated expiry makes extending a signed URL a matter of editing eight bytes, and a variable-width one makes `1 || "23"` and `12 || "3"` collide. **The algorithm is never read from the token**: it is chosen at construction from an explicit allowlist (`sha256`/`sha384`/`sha512`, each mapped to its raw digest length) and lives on the instance — a format that names its own algorithm lets an attacker choose how their forgery is checked, the JWT `alg`-confusion class. The prefix is a format version, not an algorithm field, so changing algorithm invalidates outstanding tokens rather than trusting them. **The expected payload length is the allowlist's, never the token's** (ADR-0054's fixed-length finding, which probed a correct GCM tag *prefix* being accepted at any length). **The MAC key is derived, not the caller's**: `hash_hkdf(algorithm, secret, 0, 'egl/utils:hmac:v1')`, so the common single-`APP_SECRET` deployment never feeds identical bytes to AES-256-GCM and to HMAC; the label is part of the format. `verify()` **authenticates before it reads** the expiry (acting on unattested bytes otherwise) and returns **void**, throwing `CryptoException` on every failure — RFC-0002's `bool|string` anti-requirement applies unchanged. Expiry is measured against FR-45's clock so no test sleeps, and the boundary is **inclusive-expired** (RFC 7519 `exp` semantics). A TTL that does not move time forward, or an expiry at or before the epoch (timestamp 0 being the never-expires sentinel), is **refused rather than encoded**. Realized r20 (item **14.4**, **ADR-0065**); verification is standard unit coverage plus three mechanism assertions per ADR-0027 (the algorithm reaching `hash_hmac()` comes from the validated property; the payload length from the allowlist; the MAC compared before the expiry is read) and a **conformance vector** pinning the whole `v1.` grammar — the comparator assertion itself lives in T-03's registry, which item 14.4 both extended and repaired (BUG-0001). No NFR budget: RFC-0003's reasoning for the clocks applies, and ADR-0040 reserves spec numbers regardless
- FR-48b Hmac key rotation, the `v2.` grammar (Security): key rotation for FR-48's tokens (issue #179, ADR-0085). `Hmac` accepts a `SecretKeyRing` (FR-40b) as well as a bare `SecretKey`; with a ring it signs under the current key as `v2.` = base64url(keyId (4 bytes) || expiry (8 bytes, big-endian) || raw MAC), and verifies anything the ring holds. Reuses FR-40b's convention unchanged -- the same derived key id, the id first at a fixed offset, an unknown id **refused rather than retried** against the other keys. **One part differs, and it carries the security property: HMAC has no AAD**, so where FR-40b binds the id with GCM's, this one puts it inside the signed bytes -- `mac = hmac(keyId || expiry || message)`. An id that were only a token prefix would let a substituted id naming another key the ring genuinely holds still verify, and would let a `v2.` body be replayed as `v1.` (stripping the id leaves a well-formed `v1.` payload, so the length check cannot refuse it). **A bare `SecretKey` keeps producing byte-identical `v1.` tokens** and a ring still verifies `v1.` ones by walking its keys, so adoption is a migration rather than a cutover -- additive under ADR-0059. Derived MAC keys are computed once at construction, one per ring key, asserted as a mechanism. No NFR budget: FR-48's reasoning and ADR-0040 both still apply, so the measurements live in ADR-0085 rather than becoming a gate

- FR-49 RetryPolicy + Retrier + the sleep seam (Support): explicit retry with backoff, replacing the ad-hoc per-project version that is usually wrong in one of three ways the review board named -- no jitter, retrying non-retryable failures, unbounded total time. **`RetryPolicy` is a pure value object** (max attempts, jittered exponential delay, a retryable-exception allowlist, an optional total wall-clock deadline); it decides and never acts, so it holds no clock and no sleeper. **`Retrier` owns the loop** -- leaving it to each consumer would move the ad-hoc code rather than replace it -- and is consumed **opt-in** by `HttpClient` and transaction callers, never implicitly, because a non-idempotent operation retried once is a duplicate write. **FR-45's clock is not sufficient and a second seam is required**: PSR-20 answers what time it is and nothing in it waits, so `Support\{Sleeper, SystemSleeper, FrozenSleeper}` ships both halves per ADR-0062's rule, and **`FrozenSleeper` advances the `FrozenClock` it is given by exactly what it was asked to wait** -- the coupling that makes 'tests never sleep' and 'the deadline is exercised' the same run instead of a trade. **Jitter is structural, not a flag**: full jitter over the exponential ceiling, no argument disables it, asserted by a distribution test plus a mechanism assertion (no parameter names jitter; `delayFor()` holds the draw verbatim and contains no conditional) because an un-jittered return satisfies every band assertion. **The deadline bounds the loop, not an attempt** -- it cannot end an operation already running, so what it guarantees is that no new attempt begins past it; bounding a single hung attempt stays ADR-0049's wall-clock job, and a loop deadline over an unbounded attempt is the same false comfort one level up. A delay that will not fit is **refused rather than shortened** (a clamped backoff retries soonest exactly when the dependency is struggling). Failure is **transparent**: the last exception is rethrown unwrapped, a non-retryable one immediately, and an optional `onRetry` observer is how a caller learns retries happened -- which keeps `Support` clear of `Errors` (ADR-0029). Refused at construction rather than clamped: fewer than one attempt, a multiplier below 1.0, a ceiling below the base delay, a zero deadline (null means none), an empty allowlist, a non-`Throwable` in it. Accepted bounds are typed plainly and returned ones narrowly -- a `positive-int` parameter makes its own runtime refusal unreachable and therefore untestable. **Non-goal, stated:** no circuit breaker; that is shared cross-call state, not a parameter. Realized r21 (item **14.5**, **ADR-0066**); verification is standard unit coverage plus three mechanism assertions per ADR-0027. No NFR budget: RFC-0003's reasoning for the clocks applies, and ADR-0040 reserves spec numbers regardless

- FR-50 RateLimiter + RateLimitPolicy + RateLimitDecision + RateLimitStore and two stores (Security): an in-library throttle for the call sites this group already serves, designed in full by ADR-0061 and implemented at item 14.7 (ADR-0067). **A token bucket per key** — capacity plus a refill interval — chosen because a fixed window's boundary burst (2x the intended rate for an attacker straddling the edge) IS the "resettable windows" defect issue #91 was filed against; a sliding log lets the abuser set the defender's memory cost; a sliding-window counter is an interpolated estimate sold as a limit; GCRA is the same control with arithmetic a reviewer takes on faith. **The store seam is compare-and-swap, not get/set** — the load-bearing choice: a get/set store cannot be composed race-free by any caller (two nodes read one remaining token, both approve, and the limit is exceeded BY the limiter at exactly the concurrency a brute-force attack produces), so with get/set every backend implementor inherits a check-then-act race and no library code can close it. The limiter runs read -> refill -> consume -> writeIfVersion, retrying a lost CAS a **bounded** three times and **refusing** on exhaustion, because contention on a throttled key is evidence for denial. **A store failure is never a decision**: `RateLimitStoreException` propagates so the caller — the only party who knows whether this endpoint prefers lockout or exposure — chooses, and the documentation says that a fail-open catch must be loud. **Keys are hashed at the limiter's boundary**, `hex(sha256(len(ns) || ns || len(key) || key))`, which removes store-syntax injection (including a path traversal into this library's own file store), unbounded per-key storage, and content-shaped timing — once, rather than by auditing N consumer-written stores; the fixed-width length prefixes are the domain separation that keeps `('ab','c')` and `('a','bc')` apart. **Time comes from FR-45's clock** and elapsed is `max(0, now - lastRefill)`, so a behind-clock node refills **zero** and can under-grant but never over-grant — skew degrades toward strictness. Refill is exact integer arithmetic over microseconds per token, the interval **rounds up** so the effective rate is never faster than configured, and `lastRefill` advances by whole tokens so the sub-token remainder carries (setting it to `now` makes a frequently-polled key refill more slowly than a quiet one). TTL is `capacity x interval`, the point at which a forgotten bucket and a full one are indistinguishable. **Two stores ship, each stating its enforcement scope in its own first sentence**: `ArrayRateLimitStore` (one process — under PHP-FPM, one request) and `FileRateLimitStore` (every worker on one machine, built on FR-28's `File::update()` so the version check happens inside the exclusive lock, with the expiry stored in the file rather than taken from `mtime`). **A rate limit exists at the scope its store is shared and nowhere else** — multi-node enforcement needs a consumer-implemented store over Redis or equivalent, and this library ships no network client (NFR-08). **Deliberately absent:** no circuit breaker, no PSR-15 middleware, no automatic wiring into `HttpClient`/`Session` (FR-49's opt-in rule), no in-library network store. Realized r22 (item **14.7**, **ADR-0061** design + **ADR-0067** implementation); verification is standard unit coverage plus the adversarial cases issue #91 named (clock skew, burst at exactly capacity, CAS contention, a key traversal/collision corpus), the store contract exercised against **both** shipped stores, and three mechanism assertions per ADR-0027 — the key path compares nothing, elapsed clamps at zero, and the CAS loop is bounded by a constant (an unbounded one hangs a suite rather than failing it). No NFR budget: the guarded path costs ~100 ms of Argon2id by design and the limiter's job is to be invisible next to that; ADR-0040 reserves spec numbers regardless
- FR-56 Str batch — identifier validators, display masking, truncation, and a `snake_case()`/`camelCase()` pair (Support): `isUuid(value, version?)` and `isUlid(value)`, predicates over RFC 9562's 8-4-4-12 layout / the RFC 4122 variant bits and Crockford Base32 respectively — never throwing on a malformed value under test, and `isUlid()` additionally refuses the first-character overflow (`8`-`Z`) that alphabet-and-length checks alone would miss, since only `0`-`7` is reachable within the 48-bit timestamp `ulid()` can produce. `mask(value, keepStart, keepEnd, maskChar, maskLength)` hides the middle behind a **fixed-length** run of `maskChar` regardless of how much was actually hidden — the security property, not a formatting choice: a masked value whose length still varies with the input leaks exactly what masking exists to hide — and **refuses** rather than silently returning the value unmasked when `keepStart + keepEnd` covers the whole value; the refusal message states character counts only, never the value. `truncate(value, length, suffix)` counts Unicode code points, accounts for the suffix **inside** the length budget, returns `value` unchanged when it already fits, and refuses a `length` shorter than `suffix` rather than returning a bare fragment. `snakeCase()`/`camelCase()` complete the case family `pascalCase()` opened (FR-31): both share one word-splitting engine (existing separators normalized, then a camelCase/acronym-aware boundary inserted — an uppercase run splits before the member that opens a new lowercase word, so `"APIKey"` becomes `"api_key"`, not `"a_p_i_key"`; a digit stays with the letters before it unless directly followed by an uppercase letter), which is what makes `camelCase(snakeCase($x)) === $x` hold for any `$x` already in camelCase — the round trip a `#[MapFrom]` convention (roadmap item 15.4) depends on. Case mapping is ASCII-only, `pascalCase()`'s existing rule. Realized r30 (item **15.1**); no ADR (additive helpers on an existing class, items 2.2/2.4's precedent) and no new exception type — every refusal is a plain `InvalidArgumentException`, `Str::random()`'s and `Str::pad()`'s existing convention for a caller-error over a runtime failure
- FR-57 Str batch — line-ending normalization, codepoint-safe length/substr, and the segment-extraction family (Support): `before`/`after`/`beforeLast`/`afterLast(value, needle)` return `?string` — `null` on a miss, **never `value` unchanged** (the probing arm of RFC-0004's missing-value grammar; returning the untouched subject would be a silent guess about caller intent), with `before()`/`after()` proven (not merely tested) to satisfy `before($s,$n) . $n . after($s,$n) === $s` whenever `$n` occurs, since both are computed from the same `strpos()` call's position. `between(value, start, end)` finds `end` starting **after** `start`'s match, not merely anywhere in `value`, so `between('<a><b>', '<', '>')` is `'a'`, the first complete span; `start === end` composes as expected. All five operate on bytes, which is what keeps them multibyte-safe without a `u`-mode dependency — a cut only ever lands at a byte offset where a (necessarily-valid-UTF-8) needle was actually found, so neither half can end mid-character. An empty needle is refused everywhere, including inside `containsAny(value, needles)`'s list — checked in a validation pass **before** any matching, so the refusal cannot depend on which needle happens to match first. `normalizeEol(value, target = Eol::Lf)` collapses all three line-ending conventions a text file can carry (`\r\n`, lone `\r`, `\n`) to `\n` first, **in that order** (CRLF before a lone CR, or CRLF would leave a stray LF behind), then expands to `target`; idempotent, and a value already in `target`'s form returns unchanged. `Support\Eol` is a two-case enum (`Lf`/`CrLf` only — a lone `\r` is a normalization source, never a target anyone asks to produce). `length(value)` and `substr(value, start, length?)` are codepoint-safe over `preg` `u`-mode (ADR-0019's mechanism, one public home replacing N private `preg_split('//u', ...)` copies); `substr()` is built on `array_slice()` over the codepoint list rather than reimplementing offset arithmetic, which gets native `substr()`'s full negative-start/negative-length/`null`-means-to-the-end contract for free, at codepoint granularity; both refuse invalid UTF-8 (`transcode()`'s strict-by-default stance). Realized r31 (item **15.2**); no ADR (items 2.2/2.4's precedent) and no new exception type — every refusal is the existing `InvalidArgumentException` convention
- FR-51 DataTransferObject::toArray() + JsonSerializable (Dto): the exact inverse of FR-01's hydration, driven by each constructor parameter's **declaration** rather than the value's runtime type — the choice that makes `X::fromArray($x->toArray()) == $x` hold **by construction** for every `$x` the hydrator can produce (ADR-0086 §1; a runtime-type rule breaks exactly at `mixed`/untyped positions, where a converted enum re-hydrates as a plain scalar with every "no exception" test still green). Conversion mirrors hydration branch for branch: nested DTOs recurse; backed enums become their backing value; a `#[CollectionOf]` collection becomes a list (DTO elements as arrays, backed-enum elements as backing values); everything hydration passes through untouched — builtins, `mixed`, unions, plain arrays (never walked inward), attribute-less collection elements, instances of classes outside the conversion vocabulary — comes back **as-is**, so the output is plain data exactly as far as the declarations are plain. **A position DECLARED as a pure (non-backed) enum is refused with its path** (`ticket.direction`, `directions.0`): the declaration put the value in the enum vocabulary and gave it no data form, and both non-refusal behaviours fail later and worse (a case name will not re-hydrate; a passed-through instance detonates inside `json_encode()` naming nothing). The refusal is declaration-driven like every other branch — a pure enum in an opaque (`mixed`/attribute-less) position passes through as-is and round-trips — and per-element for collections, so an empty pure-enum collection still exports `[]`. Variadic and non-promoted constructor parameters are refused (they cannot be read back; FR-02's wither constraint, shared mechanism). `jsonSerialize()` returns exactly `toArray()`, so `json_encode($dto)` and the array form cannot drift. **Companion widening (ADR-0086 §2): `#[CollectionOf]` naming a backed enum now hydrates elements from backing values too** — the element-level mirror of FR-01's top-level enum rule, previously an asymmetry (a decoded JSON list of enum values did not hydrate), made load-bearing by export producing exactly such lists. Export is interpreter-only (no ADR-0013 compiled variant — one implementation; the round-trip suite still crosses compiled hydration with interpreted export), and export takes no options. Realized r32 (item **15.3**, **ADR-0086**); verification is the T-01 round-trip suite (`fromArray(toArray($x)) == $x` plus the fixed-point property over the whole matrix) and a recorded-not-budgeted benchmark subject (ADR-0040)

## 6. Verification & Test Strategy

Five suites (spec s7): T-01 DTO hydration matrix (nested, collections, nullables, enums, strict/lenient, withers, missing-key cases per RFC-0001 R-4); T-02 injection suite (fuzzed value payloads reach the driver only as bound parameters via query-log assertion; identifier injection throws DatabaseException; LIKE-wildcard escapes); T-03 session/CSRF integration against a real php -S process (cookie flags HttpOnly/Secure/SameSite, session id changes across regenerate() and the pre-rotation identifier ceases to resolve, constant-time comparison verified by mechanism assertion per ADR-0026 §7 — positively, that `hash_equals()` is the comparator on every secret-comparison path, and negatively, that `==`, `===`, `strcmp()`, `strncmp()` and equivalents are absent from those paths — cross-session token rejection); T-04 transaction semantics (exception -> rollback -> rethrow; savepoint nesting); T-05 property tests (Json round-trips, Str::slug idempotence, Env boolean coercion table). Plus: OWASP XSS cheat-sheet corpus per Escaper context (snapshot suite); DOM-bypass corpus for richText(); Hash argon2id/bcrypt-fallback matrix; bridge conversion-fidelity contract tests in egl/utils-psr7-bridge CI (imported ADR-002). CI proves failure via the NFR-07 gate set.

**r3 (RFC-0002)** adds nine suites: T-07 HttpClient against a live `php -S` origin (T-03's
process discipline); T-08 Csv property/round-trip + formula-guard corpus, both flag states;
T-09 Crypto vectors — tamper, wrong key, truncation, nonce uniqueness across 10^5 tokens,
version-prefix handling; T-10 mail header-injection corpus, plus a **wire-capture leg** against a
real MTA — msmtp relaying into a Mailpit sink — asserting envelope-recipient delivery for `bcc`,
RFC 2047 subject round-trips across 2-, 3- and 4-byte and folded widths, and the envelope sender's
arrival (issue #101, ADR-0078; configured by `EGL_TEST_MAILPIT_URL`, skipped when unset and red when
configured and unreachable); T-11 router matrix
(404/405/Allow/params); T-12 logger routing matrix; T-13 gateway/statement injection —
ADR-0017's 29-payload corpus re-run through Repository/TableGateway with the
placeholder-only PDO-boundary assertion; T-14 FileSequence under concurrent processes (no
duplicates, cap enforced); T-15 RowNormalizer policy table.

**T-13, as delivered (r12, item 10.5)** — two legs, not one. The **value leg** is the corpus
above through every value-accepting gateway path (`insert`, `find`, `findBy`, `findOneBy`,
`update`, `updateBy`, `deleteBy`, `MutationBuilder` directly, `Repository::fetchAll` with
hand-written SQL, inside `withTransaction`, and with a `RowNormalizer` configured), plus the
consequence assertions a boundary check cannot make: the payload round-trips through hydration
intact, a tautology criterion matches and deletes nothing, and **the two parameter groups of an
`UPDATE` bind in order** (`SET` before `WHERE` — swapped, the statement still runs and writes the
criterion into the column, which no syntax-level assertion would see). The **identifier leg** runs
the hostile-identifier corpus over every surface where a column name can arrive from a caller —
criteria keys and value keys on each operation, plus the table name — and asserts not only the
refusal but that **nothing was prepared**: a refusal issued after the statement reached the driver
is a refusal that arrived too late, and a round-trip assertion cannot tell the two apart. Both
corpora live in one fixture shared by T-02, T-13 and the builder suites.

Toolchain: built with Composer (PSR-4 autoload), tested with PHPUnit (Pest optional), checked with
PHPStan max level (type soundness); PCOV for coverage, coverage target ≥ 90% line. Every functional and
non-functional requirement above maps to a CI gate (see [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml)).

### r2 rationale — why T-03 asserts a mechanism instead of measuring time

The original requirement asked for a timing test. It was measured before being changed, and the
signal such a test depends on is not there to be measured.

A timing test distinguishes `hash_equals()` from `===` by exploiting the fact that `===`
short-circuits on the first differing byte, so an early difference should be measurably faster
than a late one. On 64-character tokens, 2,000,000 iterations × 5 rounds, PHP 8.3.1:

| scenario | median ns/op | within-scenario spread |
|---|---|---|
| `===`, differing at byte 0 | 101.517 | 2.63 ns |
| `===`, differing at byte 63 | 104.352 | 2.12 ns |
| `hash_equals()`, differing at byte 0 | 232.103 | 38.22 ns |
| `hash_equals()`, differing at byte 63 | 227.929 | 29.85 ns |

The gradient the test needs — `===` late minus early — is **+2.8 ns/op**, against a worst
within-scenario noise of **38 ns/op**: the signal sits roughly **13× below the noise floor** on an
idle developer machine. `hash_equals()`'s own gradient comes out **negative** (−4.2 ns/op), which is
noise with a sign. Over HTTP, as T-03 runs, 2.8 ns sits **six orders of magnitude** below request
latency; shared-vCPU CI runners are noisier still.

**Scoping.** The constant-time property *of `hash_equals()` itself* is PHP's contract, verified
upstream in PHP's own test suite; re-deriving it here would be testing someone else's implementation
through a worse instrument. The property that exists at *this* layer is **which comparator the code
invokes** — and that is decidable exactly, from the source, with no measurement at all. The
mechanism assertion tests that property, deterministically, in both directions.

**Rejected alternatives.** Asserting that `hash_equals()` is measurably *slower* than `===` (a 2.3×
gap, comfortably above noise) tests an implementation artifact with an inverted failure profile: red
on a legitimate PHP optimisation, green on a slow but non-constant-time comparator. A full
statistical (dudect-style) test applies the right technique at the wrong abstraction layer — at this
signal-to-noise ratio its discriminative power is zero, so it would be either flaky or tuned into
vacuity.

T-03 therefore ships with its behavioural suite and no timing test, and this is an amendment rather
than a standing deviation: there is nothing left to track.
