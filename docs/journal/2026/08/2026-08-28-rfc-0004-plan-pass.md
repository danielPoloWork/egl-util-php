## What the negotiation actually decided

RFC-0004 fixed the architecture and the partition, so the plan pass's real decisions were four:

- **Item order inside M15 is load-bearing, and the roadmap says why at each point** — the
  `Str` batches land first (15.1/15.2) because `#[MapFrom]`'s convention and M16's `Length`
  rule consume them; `toArray()` (15.3) lands before the mapping that must invert it (15.4).
- **The circuit breaker split into decide (18.6) + implement (18.7)**, item 14.6/14.7's shape
  for the same component family: RFC-0004 deliberately left placement open (`Security` vs
  extracting the CAS store contract to `Support`), which makes the decision its own deliverable.
- **Twenty-one items carry the machine route; four carry a recorded raise.** With type labels on
  every source issue (the gap RFC-0003's plan pass had to caveat), `route_advice.py --issue N`
  resolves sixteen issues to `frontier-reasoning / extra` on the protected `label:adr` floor and
  four (#197, #203, #207, #208) to the `fast / low` floor — no rule matches a bare `feat`. The
  tech-lead raised those four to `fast / medium` (only-raise, ADR-0017): multibyte-boundary
  corpora (item 12.4's width lesson) and policy tables are not `low`-effort work. The raise is
  stated at each item rather than silently diverging from the tool.
- **M18's size finding (RFC-0004 R3) is recorded, not acted on**: seven items exceeds M14's
  five, and 18.1–18.2 are the natural cut line if capacity wants one — moot under sequential
  solo capacity, so the milestone stays whole with the cut line named.
