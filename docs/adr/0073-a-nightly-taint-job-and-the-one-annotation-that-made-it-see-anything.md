## Context

PHPStan runs at max level on every PR, and in this library the type system carries real security
weight: `SqlStatement::literal()` takes a `literal-string`, which is a *proof* that no runtime value
sits in that SQL text (ADR-0039, ADR-0041). What PHPStan does not do is **taint tracking**. It can
say "this string is a literal"; it cannot say "this string came from `$_GET` and reached
`PDO::prepare()` eleven calls later." Those are different questions, and only the second is about a
flow.

The review board's Senior Security Engineer asked for a scheduled Psalm `--taint-analysis` run over
Database, Http and Mail, installed outside the dependency graph the way the BC checker and Infection
already are.

## Decision

**A nightly `taint` job in `nightly.yml` runs Psalm `--taint-analysis` over the production tree
against a triaged baseline, and `SqlStatement::composed()` gains a `@psalm-taint-sink` annotation
without which the job would have been worth very little.**

### 1. Psalm is configured as a taint checker and nothing else

The config is `psalm-taint.xml`, deliberately *not* Psalm's default `psalm.xml`, and every
invocation passes `--config` explicitly. `errorLevel` is `8`, Psalm's most permissive setting — which
is correct rather than lax, because `--taint-analysis` reports taint issues and nothing else, so the
level governs only the questions this run is not asking. The alternative is two general-purpose
analysers disagreeing about ordinary types, with a second baseline to keep true; the filename is
there so nobody drifts into that by running `vendor/bin/psalm` with no arguments.

The test and benchmark trees are excluded. They feed hostile strings into the library on purpose —
that is what the T-02 and T-13 injection corpora *are* — and analysing them would report those
suites doing their job, burying the findings this exists for.

### 2. Pinned to Psalm `^5.26`, and the reason is reproducibility

Psalm 6 requires PHP `>= 8.3.16`; the maintainer's machine runs 8.3.1. Pinning 6.x would mean a
baseline generated in CI and never regenerated where someone can read the code beside it — and a
baseline nobody can reproduce locally is one that rots into a list of suppressions nobody re-reads.
5.26 runs in both places, so the baseline committed here is the baseline CI compares against, and it
was generated by hand on this change. Constrained rather than floating for ADR-0031's reason as
well: a tool whose findings move between runs makes a baseline unreviewable. Revisit when the local
PHP floor moves.

### 3. Nightly and non-blocking, but the job itself goes red

Issue #103 asks for a job *"advisory at first, with a triaged baseline so new flows fail loudly."*
Those pull against each other, and the reading taken here is: **advisory means it blocks no merge**
— it is scheduled, so no PR waits on it — **while a flow outside the baseline still fails the job**.
The alternative reading, `continue-on-error: true`, produces a scheduled job that reports findings
without ever failing, which is the vacuous-green shape this repository has had to go back and fix
six times. Promotion to a PR gate is a later decision the mechanism already supports: it exits
non-zero today. *This interpretation is flagged in the PR rather than assumed silently.*

`findUnusedBaselineEntry="true"`: a baseline entry that no longer matches anything fails the job. A
suppression that has outlived its finding is how a baseline stops describing the code.

### 4. `SqlStatement::composed()` is annotated `@psalm-taint-sink sql $sql`

This is the part that made the difference between a job worth running and a green tick.

Out of the box, Psalm **did not** detect a `$_GET` value concatenated into SQL and passed through
`SqlStatement::composed()` to `DatabaseConnection::select()`. Verified by planting exactly that
flow: the run came back *clean*. Psalm loses the taint at the value object's boundary — the string
goes into a private constructor, becomes a property, and comes back out at `PDO::prepare($statement->sql)`
with the connection broken. A direct `$this->pdo->prepare($_GET['name'])` **was** caught, so the sink
itself works; it is the laundering through this library's own type that defeated it.

`composed()` is the one documented door where `literal-string` is given up on purpose (ADR-0041).
Its docblock asks the caller to assert that nothing from outside the program is in that text.
`@psalm-taint-sink sql $sql` turns that human assertion into something a machine can refuse — and
with it, the same planted flow is caught. PHPStan ignores the tag, so it costs nothing at max level.

It is deliberately **not** put on `literal()`, whose `literal-string` parameter PHPStan already
proves.

### 5. The two baseline entries are read, not waved at

Both are `Errors/ExceptionHandler.php:165` — `echo Json::encode($document)` — and both are **true
flows Psalm traced correctly**: a throwable's message and trace reach output. Neither is a
vulnerability, for reasons the analyser structurally cannot see:

- the response is `Content-Type: application/problem+json`, set four lines above the sink, so the
  `TaintedHtml` sink is not the sink Psalm thinks it is;
- `json_encode()` escapes the quote, which is what `TaintedTextWithQuotes` asks about;
- and above both, **the control is a branch**: `problem()` returns early with a fixed `detail`
  string unless `$debug` is true, which defaults to false and which ADR-0029 decided. Taint
  analysis does not model a branch as a sanitizer, and it is right not to.

The full triage, including what would *invalidate* it, is in `docs/security/taint-analysis.md` —
because a baseline entry whose justification lives only in a commit message is one nobody will
re-read.

## Alternatives Considered

- **Add Psalm as a dev dependency.** Rejected for ADR-0031's reason, unchanged: Psalm's own PHP
  floor is above this library's 8.1, so it would either break the 8.1 matrix cell or abandon the
  8.1 promise.
- **Replace PHPStan with Psalm.** Rejected outright. PHPStan at max is the gate the whole codebase
  was written against, `literal-string` included; swapping analysers to gain taint tracking would
  trade a proven property for a new one.
- **Run it as a PR gate now.** Rejected as premature, not as wrong: the baseline has existed for one
  day and nothing has yet exercised it against a real change. Nightly first, promote on evidence.
- **`continue-on-error: true` for a purely advisory job.** Rejected in §3 — a job that cannot fail
  is a job nobody reads.
- **Suppress the two findings with `@psalm-suppress` in `ExceptionHandler`.** Rejected: it would put
  security-tool annotations in production code to silence findings, where the baseline keeps them in
  one auditable list. The one annotation this ADR *does* add to production code goes the other way —
  it makes the tool see **more**, not less.
- **Registering this control in `docs/compliance/README.md`.** Deferred, deliberately: that register
  is still empty, and adding this one row while ADR-0014's real prepares, ADR-0015's allowlist,
  ADR-0022's Argon2id and ADR-0026's CSRF seam all remain unregistered would make the register look
  more complete than it is. Populating it is its own item.

## Consequences

- **No production behaviour changes.** The only edit under `src/main` is a docblock tag PHPStan does
  not read; 3 191 tests and PHPStan max are unmoved.
- **CI grows one nightly job** (~2–3 minutes: a throwaway Psalm install plus one analysis). Nothing
  on the PR path is slower.
- **A new tainted flow into SQL, HTML or `mail()` fails the nightly** rather than waiting to be
  noticed in review.
- **`grep composed(` gained a second reader.** ADR-0041 made that grep the review list for the
  escape hatch; the annotation means the nightly does that reading too.
- **Known limit, stated rather than implied:** taint tracking is not a proof of absence. Psalm
  follows the flows its stubs know about, and the `composed()` experiment above is direct evidence
  that a real flow can pass through this library's own abstractions unseen. A green run means "no
  flow I can follow." Where a value object stands between a source and a sink, an annotation is what
  restores the connection — and there may be others not yet found.
